# Mini‑exercice gamifié : « Construisons notre première classe »  

## Type de ressource  
Mini‑exercice interactif (activité en ligne ou sur papier) découpé en plusieurs étapes, chaque étape étant visualisée par une **barre de progression**.

## Objectif pédagogique  
Comprendre le rôle d’un **constructeur** dans une classe Java : comment il initialise les attributs d’un objet et comment il diffère d’une méthode ordinaire.

## Objectif comportemental  
Renforcer la **motivation** des apprenants en rendant visible, à chaque instant, leur avancement dans l’exercice.

## Élément de jeu utilisé  
**Progress Bar** – barre de progression affichée en haut de l’écran (ou dessinée sur le support papier) qui se remplit proportionnellement au nombre d’étapes validées.

## Activité proposée  

L’activité se déroule en **trois étapes** successives. Chaque étape débloque la suivante et fait avancer la barre de progression de 33 % (ou 1/3).  

### Étape 1 – Découverte du squelette d’une classe  
1. On fournit le squelette suivant (sans le constructeur) :  

```java
public class Person {
    private String name;
    private int age;

    // TODO : ajouter le constructeur
}
```  

2. L’apprenant doit **identifier** les deux champs (`name`, `age`) et expliquer, en une phrase, pourquoi ils ont besoin d’être initialisés.  

*Barre de progression* : passe de 0 % à 33 % dès que la réponse est soumise (validation par l’enseignant ou par le système).  

### Étape 2 – Écriture du constructeur  
1. L’apprenant écrit le constructeur qui initialise les deux attributs à partir de paramètres :  

```java
public Person(String name, int age) {
    this.name = name;
    this.age = age;
}
```  

2. Il copie‑colle son code dans l’interface (ou le rédige sur la feuille) et clique sur **« Vérifier »**.  

*Barre de progression* : passe à 66 % si le code compile (ou si le correcteur manuel indique « correct »).  

### Étape 3 – Mise en pratique  
1. On propose un petit programme test :  

```java
public class Main {
    public static void main(String[] args) {
        Person p = new Person("Alice", 25);
        System.out.println(p);
    }
}
```  

2. L’apprenant doit **expliquer** ce qui se passe lorsqu’on exécute `new Person(...)` : le constructeur est appelé, les champs sont initialisés, etc.  

*Barre de progression* : passe à 100 % lorsque la réponse est validée.

## Feedback donné à l'apprenant  

| Étape | Feedback automatisé / manuel | Exemple de message |
|-------|-----------------------------|--------------------|
| 1 | **Positif** si la fonction du constructeur est correctement identifiée. | « Bonne observation ! Les champs `name` et `age` doivent être initialisés pour que chaque objet `Person` possède ses propres valeurs. » |
| 2 | **Correctif** si le code ne compile (ou si le correcteur indique une erreur). | « Il manque le mot‑clé `this` ou les paramètres du constructeur. Revérifie la syntaxe : `this.name = name;` » |
| 3 | **Encourageant** avec rappel du rôle du constructeur. | « Exact ! Le constructeur crée l’objet et initialise ses attributs. Tu viens de voir le processus complet. » |
| 100 % | **Badge de complétion** (optionnel) et encouragement à poursuivre. | « Félicitations ! Tu as terminé l’exercice sur les constructeurs. Continue ainsi pour les prochains concepts OOP. » |

## Utilisation par l'enseignante  

1. **Préparer** le support : créer une page web ou un document avec les trois blocs d’étapes et insérer une barre de progression (ex. widget HTML/CSS ou tableau à cocher).  
2. **Distribuer** le mini‑exercice en classe ou en devoir à la maison.  
3. **Collecter** les réponses :  
   - En ligne : le bouton « Vérifier » déclenche la validation et met à jour la barre.  
   - Sur papier : l’enseignante coche chaque case et trace la barre à la main.  
4. **Débriefer** : à la fin de la séance, passer en revue les réponses de l’étape 3, insister sur le rôle du constructeur et répondre aux questions.  
5. **Suivi** : enregistrer le niveau de complétion (0 %–100 %) dans le tableau de suivi des compétences pour chaque élève.

## Justification  

- **Progress Bar** (ontologie) : « La barre de progression permet de visualiser l’avancement de l’apprenant et de renforcer sa motivation ». En découpant l’activité en trois micro‑objectifs, chaque avancement visible alimente le besoin de progression du profil **Socializer**, qui aime voir son progrès et partager ses réussites.  
- **Mini‑exercice** : correspond exactement à la recommandation de l’agent précédent (« Utiliser une barre de progression pour guider les étudiants dans une activité étape par étape sur les constructeurs Java »).  
- **Séquençage** : le style de compréhension séquentiel des apprenants est respecté : ils passent d’une découverte (étape 1) à une mise en pratique (étape 2) puis à une réflexion (étape 3).  
- **Objectif pédagogique** : chaque étape cible explicitement la compréhension du rôle du constructeur, du point de vue de l’initialisation d’état d’un objet.
